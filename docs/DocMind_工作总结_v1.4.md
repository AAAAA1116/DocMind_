## 二、项目定位与技术栈

企业内部知识库问答系统，全链路为：

```
文档加载 → 切分 → 向量检索(+BM25 混合/重排) → DeepSeek 生成 → Streamlit 界面
```

| 环节 | 实现 |
|---|---|
| 加载 | `loader.py`，按扩展名分发 pdf / docx / txt / md |
| 切分 | `splitter.py`，迭代式窗口切分（v1.3 重写） |
| 向量 | `BAAI/bge-small-zh-v1.5` + ChromaDB（`core/embed_store.py`） |
| 混合 | 自研 Okapi BM25 + RRF 融合（`core/hybrid.py`，仅新增依赖 `jieba`） |
| 重排 | `BAAI/bge-reranker-v2-m3` 交叉编码器（`core/reranker.py`，**默认关**） |
| 生成 | DeepSeek（OpenAI SDK，`core/llm_client.py`） |
| 编排 | `core/rag_chain.py`，两开关正交分派纯向量 / 混合两条路径 |
| 界面 | `app.py`（Streamlit，增量入库逻辑内联在此） |
| 评测 | `eval/run_eval.py` + RAGAS 0.4.3 + `eval/dataset.jsonl`（30 条黄金集） |

运行时：Python 3.12 + venv。硬件上限：**4 逻辑核 / 2 线程 / 无 CUDA** ——
这是后续所有耗时结论的物理前提，不是代码问题。

## 五、核心评测数据

### 5.1 语料与评测集现状

- **正式库 9 个文件 / 458 块 / 21.9 万字**（7 份企业制度 PDF + demo txt/md），无短块。
- 语料来源：巨潮资讯网的「公司章程 / 信息披露管理制度 / 内部控制制度」公告 ——
  这类文本才是企业内网文档的味儿：叙述性长文本 + 条款编号密集（第一条/第二条…）。
- 归档区 `data/uploads/_attic/`：3 份年报 + 旧的虚构规章制度（**move 未删**）。机制上
  `app.stored_files()` 只扫 uploads **根目录的文件**（不递归），**子目录天然隔离**。
- 评测集 `eval/dataset.jsonl` 重写为 **30 条**：事实 19 / 转述 4 / 负例 3 / 对比 2 / 多跳 1 / 流程 1，
  含大量「同题异司」对照。

### 5.2 四配置对比（30 条真实语料）

| 配置 | 忠实度 | 相关性 | 召回 | 精度 | 误拒率 | 平均耗时 |
|---|---|---|---|---|---|---|
| 纯向量 K=3 | 0.7670 | 0.6854 | 0.5691 | 0.4321 | 26% | 910 ms |
| + 混合 K=3 | 0.8539 | 0.7775 | 0.7222 | 0.6111 | 11% | 1,037 ms |
| **+ 混合 K=8（当前默认）** | 0.9423 | **0.9031** | 0.8519 | 0.5804 | **0%** | **1,560 ms** |
| + 混合 K=3 + 重排 | **0.9669** | 0.8869 | **0.8642** | **0.9105** | 4% | 35,672 ms |

拒答准确率四档均 100%(3/3)。结果文件在 `eval/results/`。

**三点关键读数：**

1. **混合检索几乎免费**（910 → 1,037 ms，仅 +14%）却拿走近一半收益，误拒率 26% → 11%。
   `HYBRID_ENABLED = True` 保持默认开，无争议。
2. **K=8 + 关重排 ≈ K=3 + 开重排，时间差 23 倍。** 对比开重排那档：答案相关性**反超**
   （0.9031 vs 0.8869），忠实度与召回**基本持平**（差 0.025 / 0.012，均在 ±0.06 噪声量级内），
   只有精度明显低 —— 但精度随 K 单调降是数学必然，不该当判据。
   ⇒ 这台机器上「**多喂证据**」比「**精选证据**」划算得多。
3. ⚠️ **K=8 有 1 条真退步**：q25 忠实度 0.50 → 0.00 —— 多喂进来的第 5 块噪声让模型做出
   **跨块错误归因**。**K 变大 = 召回补满 + 噪声增多，两个效应永远同时发生**，均值涨会掩盖单条倒退。

> 旧基线（10 条虚构玩具语料）已作废：召回 1.0000 是同构 + 短语料造成的虚高。

## 六、本轮（v1.4 之后）的收尾工作

顺着「剩余缺陷在哪一层」往下挖，做了 **4 个零 LLM 调用的免费实验**，结论是**全部不做**。

### 6.1 身份维度（3 个方案离线预演）→ 缺口 = 0

对**同一次检索结果**离线重排出三种口径：`any`（现状）/ `right`（只留期望文档 = 硬过滤上限）/
`idfir`（身份优先重排）：

| K | any | right | idfir |
|---|---|---|---|
| 1 | 0.4722 | 0.4722 | 0.5139 |
| **3 ★** | **0.8056** | **0.8056** | **0.8056** |
| 8 | 0.9306 | 0.9306 | 0.9306 |

- **三条曲线在所有 K 上完全重合** ⇒ **身份缺口 = 0**，硬过滤能补的空间是 0。
- top-8 的 192 个候选块里，别家文档只占 **12.5%，且没有一个含答案**。
- **成本对比**：硬过滤要改 `embed_store.search` + `BM25Index.search` + `hybrid_search` +
  `rag_chain` 等 **5~6 处**，还要处理「BM25 的 idf/avgdl 过滤后失真」「过滤后候选不足 k」
  两个陷阱；而块内嵌文件名那 **1 行**（`app.py:ingest_file`）已经把这一维做满了。
- ⇒ **不做。** 过滤这种「看起来更精确」的改动，会把一个**软错**（排序不理想，模型还能救）
  变成**硬错**（正确答案被静默排除）。

### 6.2 切分粒度对齐条款 → 上限 = 0

`_SEPARATOR_GROUPS` 三级分隔符只认 `\n\n` / `。！？` / `；，、`，**不认「第X条」**；
制度 PDF 常无 `\n\n` ⇒ 窗口内最右句末标点一般落在条款中段。实测切点对齐率仅 **19.6%**。

写了「条款边界优先 + 聚合到 chunk_size」的替代切分做消融（**0.9 秒 / 零 LLM**）：

| | 现状 | 条款对齐版 |
|---|---|---|
| 切点对齐率 | 19.6% | **78.6%** |
| 块数 | 455 | 549（+20.7%） |
| 块均长 | 502 | 435 |
| **答案同块率** | **0.9386** | **0.9386** |

变好 **0** 条 / 变平 26 条 / 变差 **0** 条 ⇒ **上限 = 0，不做。**

**机制（比数字值钱）**：① **`OVERLAP=80` 本身就是解药** —— 任何 ≤80 字的连续片段必然完整落在
相邻两块之一，而答案要点是 8~40 字短句；② 500 字窗口装 2.56 条，**单块足够容纳一整条**（条款均长约 195 字）。
⇒ 粒度错位是真的，但被「overlap」和「块比条大」两个事实同时兜住。

### 6.3 邻块扩展 → 也是 0

假设「答案就在相邻块里」（取块时顺带取 `chunk_index±1`，不用重建索引，看似极划算）：

| 方案 | 要点覆盖率 |
|---|---|
| 现状 8 块 | 0.9306 |
| 扩展 ±1（约 24 块） | **0.9306（+0.0000，0/24 条有提升）** |
| 上界 ±2（约 40 块） | 0.9444（+0.0139） |

用 **3 倍 context token 换 0 收益** ⇒ **不做**。顺带证伪了「答案分散在相邻块」：
低覆盖的 q05/q06/q26 是**「含答案的块压根没进 top-8」**（块级召回失败），邻域扩展救不了。

## 十、这轮沉淀的方法论（比代码值钱）

### 10.1 先跑免费的实验，让昂贵的实验直接失去意义

**动手前先问一句：这件事有没有一个「便宜到不用犹豫」的版本？先跑它。** 三个真实案例：

| 问题 | 昂贵做法 | 免费版本 | 结果 |
|---|---|---|---|
| TOP_K 取几 | 全量评测（20 分钟/配置） | 召回上限扫描（reference 逐字抄自原文 ⇒ 字符匹配判「块含不含答案」），**8 秒 / 0 次 LLM** | 扫出拐点 K=5~8，只对拐点跑全量 |
| 身份硬过滤有没有用 | 改 6 处代码去试 | 从**已有的同一次**检索结果离线重排口径，算出**理论上限** | 上限 = 现状 ⇒ 不用做 |
| 重排值不值 | 跑一轮 35 秒/条的评测 | 先读代码发现 `pool = max(RERANK_CANDIDATES, TOP_K)` ⇒ 免费的 `TOP_K 3→8` | 拿到 +0.09~0.13 后，重排实验失去意义 |

两条通用判据：

- **开销是「算力正比」还是「token 正比」？** token 便宜 2~3 个数量级，便宜的先做。
- **上限法**：如果便宜的方案能算出贵方案的理论上限，且**上限 ≤ 现状**，直接砍掉，不用试。

### 10.2 全部判定都是同一个形式

所有 RAG 判定（TOP_K 覆盖、`context_recall`/`precision`、`faithfulness`、拒答子串匹配、
`hdr_ratio`、BM25 词项交集、页眉重复识别）形式上完全一致：

```
Judge(x, D) = ∃ y ∈ D,  y ⪰ x        # 存在性判定，差别只在 ⪰ 多严
```

这个东西 = **证据锚** = 原子断言 + 它的锚定范围。**两个正交维度，缺一不可**：

- **内容锚**：断言在不在。实测 **89.6% 靠字面即判**
- **身份锚**：是不是同一个对象。19.4% 的原子是多文档重述，其中 **76.9% 自己不带公司名**

**核心一句话**：判定要的是**同一**（identity），向量给的是**相似**（similarity）。
同构语料上相似 ≠ 同一，**差集就是全部错误**。只调内容锚的松紧永远到不了
「内容对 ∧ 同一个对象」—— 缺的是维度，不是旋钮位置。

### 10.3 判据本身最容易出错（本轮连踩）

1. **「块首」≠「切点」** —— `OVERLAP=80` 让每块开头是上一块的尾巴，「块首有没有条款标记」
   根本测不出切点在哪。**加任何「块级」判据前先问：它测的是切点还是块首。**
2. **「看起来很像」的机制解释必须先用廉价实验证伪** —— 「q05 被劈成两块」是我按文档结构猜的，
   实测条款对齐后覆盖率 **0.571 → 0.571 一动不动**，那两个信息本来就在不同的条里。
3. **在 PDF 抽取文本上做字面匹配，第一步永远是 `re.sub(r'\s+','',t)`** ——
   `（一） 内部环境。` / `包括 3 名董事` 会把任何「连续 N 字」判据切断，把命中误判成未命中。
4. **自造判据必须做全局可达性检查** —— 不可达的要点要**剔出分母**，不是算失败。
5. **必须配别名表** —— 「新宝股份」匹配不到「广东新宝电器股份有限公司」⇒ 期望集合变空 ⇒
   判断函数对空集恒返回 True ⇒ **该题的问题被整体吞掉，看板却显示一切正常**。
   **结果太干净时，先去查判据，别高兴。**
6. **指标会说谎** —— `context_recall` 在同构语料上假阳性（别家公司的同构条款和 reference
   几乎逐字相同，ragas 只做语义比对、不知道它来自另一份文档，实测给了 1.00）；
   `REFUSAL_TEXT in text` 把半拒答判成成功作答。⇒ **必须有一层独立于指标的旁证**
   （最长公共子串 / 人工抽查 top-k 的 `source`）。
7. **污染存在 ≠ 污染有害** —— q25 混进 5/8 别家块，但覆盖率 1.00（那 5 块不含答案）。
   判身份问题必须看「混进来的块含不含答案」，只看「混没混进」会得到 12.5% 的假警报。
8. **均值涨不代表没退步** —— 跑完必看「哪几条变差了」，逐条 diff 是固定动作不是可选项。
9. **单条指标的异常值先怀疑裁判** —— 一条 `None` 能让人花半小时查一个不存在的 bug。

### 10.4 换语料是照妖镜

**语料的难度决定你能不能看见优化的价值。** 旧语料只有 10 条、全是一个文档的内容，
检索层怎么做都是满分，于是「混合检索没用」这个结论看起来无比正确 —— 直到换了真实语料才现原形，
四指标差出 +0.09~0.30。**换了真实语料后，正面收益才第一次出现。**

## 十二、难度点评

**这轮「做」的难度是 0** —— 四个实验加起来不到 1 分钟（0.9 秒 + 8 秒 + 秒级 + 58 秒），零 LLM 调用。

**真正的难点在于敢用一个 0.9 秒的实验否掉一个看起来必须做的改动。** 切点对齐率 19.6% 那个数字
非常像 bug，改它也有明确的技术路径（把条款边界加进最高优先级分隔符），任何人看到都会想动手。

**最容易踩的坑，正是我这轮踩的**：拿「块首」当「切点」，拿「很像的机制」当结论。
两次都是**判据/解释层面的错，不在实现层面** —— 而它们都会让你**信心十足地去做一件没有收益的事**。

**换一种做法会怎样**：直接改 `splitter`、重建索引、跑评测，你会拿到一组「几乎没变」的数字，
然后**无法判断是改动无效还是评测分辨不出来** —— 因为块边界全变了，BM25 的 avgdl 和
**所有历史评测结果都不可比**，你连基线都没了，会陷入「是改动没生效还是真没用」的困惑，
远比现在贵。**先花 30 秒算清楚「这个改动的收益上限是多少」，比改完再解释为什么没效果便宜得多。**
